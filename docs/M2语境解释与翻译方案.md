# M2：划词语境解释与翻译

日期：2026-10-26。当前实现版本：0.3.1（M2 用户反馈修订）。第一阶段已由用户于同日确认验收；其 0.2.0 安装包和证据，以及 M2 0.3.0 的安装包与验收报告继续保留。0.3.0 的原方案另存于 `验收证据/0.3.0/M2语境解释与翻译方案.md`。

## 精简范围

用户完成真实文字选择后，选区附近自动出现紧凑深色圆角操作条，提供“翻译”“解释”和关闭入口。出现操作条不发模型请求，点击动作后直接就近流式显示结果；原生右键菜单继续作为补充。主要面向技术文章与外语阅读。

- 解释包含原选区和所在段落，说明术语或句子的具体含义；默认约 80—180 个中文字，按需查看明确标为“用法示例”的具体情境，适用时提供最小代码。
- 翻译为符合上下文的完整中文，保留重要技术术语；英语词语或短句可按需生成“双语例句”，提供 1—2 组英文句及对应中文译文。长段落默认只保留完整翻译，避免无关入口。
- 支持流式输出、停止、复制、手动重试和关闭。关闭后继续原处阅读。
- 普通主页面与现有链接预览 iframe 均支持；已授权的普通子 frame 使用相同精确文档校验。
- 复用现有接口、模型与 Key 管理，不增加通用聊天工作台、账户、云端历史或统计。

## 实现方案

沿用现有 `contextMenus` 权限和两个原生菜单项。内容脚本在可信鼠标或键盘选区完成后捕获文字和语境，展示操作条；程序化选区变化只用于失效清理，不能触发模型。操作条按钮保持原选区，只有真实点击发送动作，后台重新查询浏览器的 frame/document 身份，并向该精确文档核取当前随机捕获标识对应的快照。来源网页不能通过修改 DOM 或 `.click()` 自动调用模型。

原生 `contextmenu` 不被拦截，Google 搜索和复制继续可用。Key 只在可信扩展后台读取，直接发送到用户配置的模型端点。本轮没有新增权限、云端存储或统计。

采集选区文本、就近可见段落、标题、URL 和选区矩形。限制选区 6,000 字符、上下文 10,000 字符；过长选区明确提示，不静默截取。排除表单、密码框、编辑器、隐藏区域和扩展自身界面。普通选择、右键和工具条共用提取逻辑；右键导致选区消失时，可使用本次文档内 60 秒以内、与 Chrome 菜单事件文字匹配的捕获。新空选区会清除旧捕获。

后台以 Chrome 菜单事件的 `tabId + frameId` 查询浏览器实际 `documentId`，只向该文档请求捕获并显示回答。回答浮层装在原 frame 内，以当前选区坐标定位并约束于 viewport。它不改变来源 URL、滚动位置或原选区。

请求通过文档绑定的 Port 更新流式状态。每次查阅具有独立 requestId；快速切换时取消旧请求，并忽略旧文档、旧 Port 和旧请求的后续输出。重试与展开使用新的请求身份。只有真实用户界面操作会提交这些命令；页面脚本的程序化点击不触发模型。

更换选区、点击空白、滚动、关闭、来源/iframe 导航和权限变化会清理对应界面并取消旧任务。链接拖动期间不显示划词操作条，保留 M1 的拖动预览。操作条与结果卡片都约束于所在 frame 的可视区域。核心答案和按需生成的示例以不同分区展示，示例入口和提示词同时调整，不能只改变按钮文字。

模型输入以结构化材料明确区分选区、上下文、标题与 URL，忽略原文内的操作指令。沿用预算规划与流式接口的超时、取消和错误处理；预算不足时先提示，不发起付费请求。停止、关闭、文档导航、权限撤销、配置变更或清 Key 会使相关任务失效，不自动重试。

## 可复现验收标准

| 项目 | 操作与预期结果 |
| --- | --- |
| 自动操作条 | 普通主页面和真实预览 iframe 完成选区即显示“翻译/解释”，模型请求数保持零；点击翻译仅发一次请求，无二次确认。 |
| 选择保持 | 操作条点击不改变原选区；完成后核心答案属于该选区，重新选择不会被旧输出覆盖。 |
| 示例语义 | 短英语翻译提供“双语例句”，确定性测试验证英文句与中文译文成对；解释提供“用法示例”，包含具体情境或最小代码。长段落不展示无关例句入口。 |
| 生命周期 | 关闭、滚动、空白点击、重新选择、导航或权限变化均清理旧状态；链接拖动、输入框和扩展回答不触发操作条。 |
| 技术解释 | 主页面选择技术术语或句子，原生菜单选择解释；近旁出现中文核心答案，模型输入包含选区和所在段落。 |
| 语境翻译 | 外语文章选择一句或一段，选择翻译；提交上下文并展示中文译文与必要原文术语。 |
| 预览内阅读 | 在 M1 页内预览的真实目标 iframe 中完成上述两种动作；读取的是目标 frame 的选区与段落。 |
| 连续 A/B | A 尚在流式输出时选择 B；界面和最终答案属于 B，A 的迟到结果与旧按钮命令不覆盖 B。 |
| 选区消失 | 菜单打开后浏览器原选区折叠，仍使用刚捕获的匹配选区；无匹配记录时提示重选，不猜测旧段落。 |
| 空选区与不可读区 | 空文字、输入框、隐藏区或无效文档不发模型请求；超限和上下文不足有明确反馈。 |
| 控制 | 停止中止连接，复制只复制当前答案；重试与展开均由显式用户动作发起，无自动付费重试。 |
| 阅读位置 | 打开、关闭浮层不改变页面 URL、scrollX/scrollY；窄屏浮层及关闭入口不越界。 |
| 原生行为 | 原生右键菜单不被拦截，Google 搜索继续保留。 |
| 身份与权限 | 浏览器文档身份、Port 与请求逐项匹配；导航、权限变化、清 Key、保存配置后不再使用旧状态发请求。 |
| 失败 | 认证、限流、模型/格式错误、网络与超时可读；无自动重试，保留已收到片段。 |

单元和后台测试覆盖选区/输入校验、提示构造、请求身份、取消与竞态。浏览器测试使用独立 profile、本地文章和模拟 SSE 服务，检查真实 DOM、选区、frame、网络载荷与浮层截图。若 headless 无法点击 Chrome 原生菜单项，使用仅存在于临时测试扩展副本中的事件仪器化，并在报告明确区分菜单选择模拟与真实浏览器行为。

真实模型语义质量与用户 Chrome 的原生菜单选择需要单独人工验收。未提供真实接口时，不将模拟输出记为真实模型结果，也不要求用户把 API Key 发到聊天。

实现参考 Chrome 官方 [contextMenus](https://developer.chrome.com/docs/extensions/reference/api/contextMenus) 与 [webNavigation](https://developer.chrome.com/docs/extensions/reference/api/webNavigation) 文档，菜单项在有选区的普通网页/frame 中出现，文档身份使用浏览器返回的 documentId。
