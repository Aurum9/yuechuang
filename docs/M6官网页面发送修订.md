# 0.8.0 官网页面发送

> 历史方案记录：该页面发送方案已停止推进。0.9.0 已移除相关设置入口，当前使用方式请参阅 [Webapp 接口修订](M6Webapp接口修订.md)。下文保留当时的方案与验证边界，不作为当前安装指引或真实可用结论。

2026-10-29。新增可选择的官网页面发送通道，用于处理旧版网页接口能读取登录和模型、发送却返回 403 的场景。旧接口尚未适配当前官网协议，保留为兼容选项。

## 已知原因与实现取舍

已授权的官网测试正常返回“连接测试成功。”。观察到官网使用 `/backend-api/f/conversation`，成功请求包含 Sentinel Chat-Requirements、Proof、Turnstile 等校验字段；旧版扩展使用 `/backend-api/conversation` 及简化请求。缺少这些步骤是重要实现缺口，尚未从插件那次 403 响应取得具体拒绝规则。

本机 Sider 5.35.3 的静态代码包含会话凭证获取、带前置校验的直接网页接口请求、流式返回，以及遇到 403 后的 guarded-tab 代理。该直接通道不要求常驻官网页面；必要时仍可能创建或复用后台标签页。证据见 [Sider 代码核查](SiderWebapp代码核查.md)。本次新通道通过官网可见输入框与发送按钮工作，其资源占用和依赖条件与 Sider 的直接通道有差别。

## 使用

1. 在 `chrome://extensions` 重新加载阅窗，关闭旧侧栏后点击图标重新打开。
2. 设置 → 侧栏对话连接 → ChatGPT 网页 → 发送方式选择“官网页面发送（推荐）”，保存。旧设置保留旧接口选择，需要主动切换一次。
3. 首次使用可点击“打开专用 ChatGPT 页面”登录或完成验证。模型在官网选择，侧栏显示“跟随官网当前模型”。“检查官网页面”只检查 DOM 就绪，不发送付费消息。
4. 返回侧栏对话并发送。后续会使用后台专用标签，用户无需切换过去。页面关闭后，下次发送会新建后台页面，并把本地已完成上下文作为新问题的一部分发送；不会自动补发失败的那一轮。

若已授权 chatgpt.com，页面模式允许直接尝试发送，不要求先检查登录。状态仍如实显示尚未验证；发送前由专用页面检查输入框、登录与页面状态。登录失效时需要用户到官网处理。

## 边界

- 专用官网标签需要存在，首次登录、验证、选模型需要用户操作官网。页面模式不会调用或复刻官网的校验算法。
- 自动创建标签保持后台；显式打开按钮会切到专用标签。已有专用标签可复用，其他用户聊天标签与草稿不会被接管。
- 本轮只同步当前发送所属的回答。草稿、附件、正在生成或手动切换会话时停止并提示，不覆盖输入，不自动重试，不切换 API Key 计费。
- 停止生成会尝试停止已确定属于本任务的官网回答。清空本地对话、关闭侧栏或失败后不复用未完成的远端轮次，OpenAI 历史保留。
- 页面模式没有读取会话凭证、Cookie、私有应用状态或网络响应；不保存登录凭据。本项目没有云端服务器，聊天仍按 ChatGPT 自身的设置保存在 OpenAI。
- 普通文字和基础 Markdown 会同步。复杂卡片、交互组件、图片、公式及工具运行界面不保证完整还原。网页更新可能使选择器失效。
- 摘要、划词、收藏与研究的连接方式保持现有范围；本次新通道用于侧栏对话。

## 验证范围

自动验证使用独立 Chromium 配置、本地拦截的官网 DOM 与模拟回答，无真实登录或额度消耗。覆盖实际生产扩展设置、侧栏、后台、隔离脚本之间的调用，另有真实 DOM 夹具测试新版官网语义标记、SPA 路由先变化、延迟挂载输入框、取消与完成边界。

官网正常发送曾得到真实回答；本次扩展 DOM 通道还需在用户 Chrome 完成一问一答和追问。浏览器工具不能操作用户的扩展内部页面，因此不会把模拟测试描述成真实账号已修复。

独立验收：切换新模式 → 首问有完整回答 → 追问沿用上下文 → 停止后不误报完成 → 新对话保留 OpenAI 历史 → 关闭后台页后再次提问可新建。任何失败均可使用“复制连接诊断”，无需提供账号凭据。
