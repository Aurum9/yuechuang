# Sider 摘要实现调查与阅窗改进

调查日期：2026-10-26。调查对象：本机已安装的 Sider **5.35.3**。结论适用于该发行版本中定位到的代码路径，服务端实现仍有未知部分。

## 已确认的客户端流程

在页内链接预览路径中，Sider 会从目标 iframe 的实际 DOM 提取内容，把正文转成文本文件上传，再以文件 ID 发起摘要请求。

```text
目标网页 DOM → 正文提取 / Markdown → .txt 文件
    → 上传文件（带 RAG 任务）→ 文件就绪 → 文件 ID + 网页摘要模板 → 流式回答
```

扩展包身份经 [Sider 官方扩展入口](https://sider.ai/extensions) 和 [Chrome 商店条目](https://chromewebstore.google.com/detail/sider-chat-with-all-ai-gp/difoiogjjojoaoomphldepapgpbgkhkb) 核对。调查仅静态读取扩展发行代码，未访问用户存储、Cookie、登录凭据，也未调用 Sider 接口。

压缩包中一行可能包含多个函数，下表同时给出 JavaScript 字符偏移，方便复核；偏移按 UTF-16 字符计数，升级版本后会变化。

## 长内容能确认到什么程度

**文件化和 RAG 任务为长内容提供了服务端处理入口。** 因此网页正文不必作为一条巨大的聊天消息直接拼进客户端请求。但客户端出现 `RAG` 标记，只能确认请求的任务类别；服务器可能针对摘要与问答使用不同策略。

以下细节尚无证据可确认：分块长度与重叠、向量模型、召回数量、是否先逐块摘要、是否采用分层归并、是否对短文件直接使用完整上下文、最终模型实际看到多少正文。不能将“上传了文本文件”解释为“最终模型逐字阅读了全文”。

官方的 [AI Chat 指南](https://sider.ai/help-center/feature-guides/ai-chat) 说明可阅读当前网页及上传文件，没有公开上述算法。[ChatPDF 页面](https://sider.ai/chatpdf) 宣传可处理很长的 PDF；产品文件容量也无法直接换算为单次模型上下文。[隐私政策 §2.3、§5.5](https://sider.ai/policies/privacy) 说明网页文本和文件会按功能需要经 Sider 服务器发送给所选模型提供方，与客户端观察到的服务端入口一致。

全篇摘要需要覆盖文章各部分。若只按某个问题检索少量相关片段，可能遗漏后半篇的重要转折。RAG 常用于问答，是否适合概括全文还取决于其检索和归并策略。

## 财新例子的判断

检查 [用户提供的新闻页](https://weekly.caixin.com/2026-10-23/102496284.html) 时，公开可读内容包含标题、导语、开头正文及章节入口；导语已经提到极左翼、极右翼和社会承担代价。Sider 的输出包含这些概括，**仅凭这份输出无法证明它读取了后续完整报道**。其政治角度可能来自导语，属于合理推断，尚无该次请求载荷证据。

阅窗旧摘要的问题需分开处理：正文抽取遗漏导语，可能造成主题理解偏窄；固定 24,000 字符限制可能造成长文尾部丢失；页面本身只加载开头，则需要诚实显示读取范围。增加上下文预算能缓解第二项，对未加载正文没有帮助。

## 阅窗 0.2.0 的实现选择

阅窗继续直接请求用户配置的 Chat Completions 接口，无需另建文件上传或检索服务。

1. 提取当前页面**已加载、可见、可访问**的正文，保留标题、描述和章节信息，移除固定 24,000 字符的开头裁切。超过 300,000 字符的资源保护上限时报告失败，避免悄悄截取。
2. 输入与输出预算足够时，用全部已提取正文生成摘要。
3. 超预算时按原文顺序完整分段，各段生成事实提要，再分层归并成全篇摘要；每段都会参与处理。中途结果明确标记为尚未完成。
4. 请求前展示预计调用次数。多次调用默认需要在界面确认；设置中可允许自动分段。停止会中断当前请求并阻止后续调用，无自动重试。
5. 显示读取范围、字符数和处理进度。登录提示、分页及可见区域裁剪等迹象会触发范围提示；不读取隐藏付费正文，也不自动跨页抓取。

分段摘要仍会压缩细节，模型也可能误读。测试中能验证正文首尾被提交、各段都参与、预算和取消生效；实际摘要质量需要用真实模型与文章评估。Token 数采用保守估算，未绑定特定模型 tokenizer；预算应按服务商的上下文限制设置。

## 页内预览的附带发现

同版本 Sider 的链接预览使用 Shadow DOM 内的普通 iframe。后台对来源标签页添加会话规则，移除 `X-Frame-Options`，关闭时清理。定位到的规则未处理 CSP 的 `frame-ancestors`，因而无法据此承诺所有网站都能嵌入。

阅窗 0.2.0 改为原生拖动链接超过 28px 后立即打开页内浮窗，无需松手；指针位于浮窗内时模糊来源页。新增的响应头规则仅对来源标签页、来源主机与目标主机的 GET iframe 请求生效，只处理 `X-Frame-Options`。站点 CSP 或其他访问规则阻止时提示在普通标签页打开。
