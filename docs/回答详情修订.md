# 回答详情修订

日期：2026-10-30。版本：0.12.0。

## 使用

在 Chrome 扩展管理页重新加载阅窗，重开侧栏，使用已保存的「ChatGPT 订阅（官方登录）」发送一条新问题。点击回答下方默认收起的「回答详情」，查看本次模型、总耗时、首字等待和 token 用量。助手 EXE 没有修改，无需重新安装或重新授权登录。

## 数据含义与范围

- 模型仅采用服务端实际返回的模型标识，不以设置中的模型代填旧消息。合法的最终模型覆盖较早事件中的模型。
- 输入、输出、合计 token 计数从成功完成的 Responses 响应提取；缓存输入和推理输出作为对应父项的子项展示，不重复相加。计数不换算为剩余订阅额度。
- 实际 0 显示为 0；部分计数缺失时显示「未返回」，不自行求和补全。全部用量字段缺失时省略用量区。没有详情的历史消息不增加空面板。
- 从实际模型 POST 发出前开始本地单调计时，首个非空回答文本记为首字等待，终态记为总耗时，包含网络和接口响应等待。登录、取凭证、读取模型列表和本机会话保存不计入。用户停止或后台被终止时不补造总耗时。
- 流式正文、来源和详情独立更新，同一消息的原生折叠节点保持稳定，状态刷新不会折叠已展开的详情。复制回答保持原始 Markdown 正文。
- 详情只作为会话显示数据，随回答保存在 `chrome.storage.session`，浏览器重启后清除。它们不会进入下一轮模型输入。恢复、更新和渲染均清洗固定字段，丢弃未知属性、非法数值和超出父计数的子计数。

本轮范围为官方订阅侧栏对话，通用 API Key、划词及跨页研究沿用已有请求协议。ChatGPT 记忆、官网聊天历史、账号额度查询和推理摘要未在本轮接入。

## 验证

- 386 项单元与集成检查通过，覆盖完成、缺失、0、异常计数、失败和取消、增量合并、按消息保存恢复及下一轮输入隔离。
- 25 项官方登录及侧栏 UI 模拟检查通过，其中新增 5 项详情验收覆盖默认折叠、键盘、更新保留展开、恶意数据过滤、复制和中断草稿。
- 16 项侧栏浏览器回归、9 项内容异常模拟和 5 项实际后台停止恢复检查通过；恢复检查确认同一文档与草稿保留，自动重发 0 次。
- 已检查 320px / 390px 的展开截图，长模型标识换行，缓存及推理子项与输入输出层级可辨，来源保留在详情上方，无横向溢出。

浏览器测试使用隔离 Chromium、本机夹具及虚构数据，没有调用真实账号、助手或模型。真实账号是否返回全部可选字段仍待用户复测；缺失字段按上述规则处理。
