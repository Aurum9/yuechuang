# 完成事件正文保留修订

日期：2026-10-30。版本：0.12.1。

## 现场现象与复现

用户在 0.12.0 的官方订阅对话中发送「哈喽」，回答短暂出现后消失，转为「回答未完成」。连接诊断显示 HTTP 200、缺失 Content-Type、`response.completed`、`status: completed` 和 `emptyText`。

诊断记录不包含实际正文或完整输出结构，无法据此判定服务端最终 `output` 的具体内容。源码中的确定问题是：遇到最终 `output` 数组时，无论其中是否附有正文快照，都会用重新拼出的字符串覆盖已收到的流式文字；拼接结果为空时就会抹掉此前已显示的回答。

本次使用「delta 哈喽 + 同一响应的 completed/error:null/output:[]」建立最小协议回归，旧实现报 `format/emptyText`。另用缺失 Content-Type、与现场相同的完成字段及虚构用量建立完整后台会话回归，旧实现把本应完成的回答变成错误。它们证明代码缺陷，不冒充真实服务端响应抓包。

## 修订规则

- 最终快照明确提供助手的 `output_text` 时，继续以其为准，包括显式空字符串。显式空正文不能用早期草稿冒充成功。
- 最终事件没有再次附上正文快照时，使用本次流内已经定稿的文字，或保留本次流已接收的有效文字。仍需收到正确的完成事件、完成状态且没有错误。
- 收集 `response.output_text.done`、`response.content_part.done`、`response.output_item.done` 中的助手正文；按输出项及内容索引替换去重，同一段文字不会因三类 done 事件出现三次。
- 来源引用绑定最终采用的正文，偏移按内容段计算。推理、工具结果、输出格式配置 `response.text` 均不作为回答正文。
- 显式拒绝答复按其文本处理；失败、中断、未完成、未支持的后续工具调用和未知助手内容继续停止，不自动重发问题，也不改变计费路径。

助手、登录与请求正文不变，无需重装助手或重新授权。本次只修订响应解析，不增加模型请求。

## 验证

398 项单元与集成检查通过，包含本次 30 项协议检查，以及从流式解析到后台对话保存、第二轮输入和回答详情的完整模拟回归。另有独立只读审查的 25 组边界检查，覆盖多内容段与输出项、三类 done 去重、显式空正文、拒绝文本、未知角色与工具、响应身份、引用偏移和错误终态。

最终构建的 25 项官方连接 UI 模拟检查、16 项侧栏浏览器回归、9 项内容异常模拟通过。模拟数据采用虚构凭证与本机夹具，没有调用用户账号或真实模型；本次现场问题仍需用户重新加载后确认。0.12.0 已有的实际后台停止恢复证据继续作为该版本记录保留。

## 用户复测

在 Chrome 扩展管理页重新加载阅窗，重开侧栏，先发送「哈喽」。检查回答保留且没有转为「回答未完成」，再展开回答详情查看接口实际返回的可选字段。此前失败的消息仍可作为未完成记录保留；新问题的成功状态单独判断。
