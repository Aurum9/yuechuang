# 0.9.0 Webapp 接口修订

日期：2026-10-29。当前为开发与验证版本，真实扩展侧栏完整对话仍待确认。

## 本次行为

ChatGPT 账号连接采用官网客户端的 Webapp 请求通路。用户在阅窗侧栏输入问题、选择账号实际可用的模型、查看流式回答并追问；插件不填写官网编辑器、不点击官网发送按钮，也不依靠官网聊天 DOM 提取回答。0.8.0 的“官网页面发送”和“跟随官网模型”入口已经移除。

当前实现需要官网页面环境承载客户端：优先复用已打开的 `https://chatgpt.com/` 页面，没有合适页面时自动创建后台固定代理标签。它只运行官网客户端 fetch，请求与回答通过受限接口同步到侧栏。首次登录、登录失效或官网要求人工验证时，需要用户亲自操作官网。代理标签可能存在，当前实现不承诺完全不占用官网标签。

本轮只改变“对话”标签的 ChatGPT 账号连接。API Key 连接继续保留，划词翻译、解释、文章摘要和跨页研究继续使用用户配置的模型 API。收藏与已存研究报告仍保存在本机。

## 使用方法

1. 在 Chrome 扩展管理中重新加载项目 `dist`，关闭旧侧栏，再点击阅窗图标打开。
2. 进入“设置 → 侧栏对话连接”，选择“ChatGPT 账号（实验）”。旧页面发送配置需要重新检查账号、选择模型并保存。
3. 首次使用点击“登录 ChatGPT”，授权 `chatgpt.com`，在官方网页亲自完成登录。已经登录时可直接点击“检查账号 / 刷新模型”。检查操作只读取账号状态与模型，不发送模型问题。
4. 从下拉框选择当前账号返回的实际模型，点击“保存对话连接”。侧栏账号对话无需填写 API Key。
5. 切回“对话”提问。回答应直接出现在侧栏，并可继续追问；正常发送无需切换到官网输入框。
6. 遇到官网要求的人工验证时，在官网完成处理，再回设置检查账号。关闭或重载代理页面、扩展后台重启后，也可能需要重新检查。
7. 失败时在设置点击“复制连接诊断”反馈。诊断只含版本、连接方式、阶段、HTTP 状态和固定错误分类，不含账号、模型、问题、回答或凭据。

“新对话”清空本机当前会话并解除远端关联，下次提问开启新的远端会话；OpenAI 历史保留。停止或失败后不会自动重发问题，不会自动切换到 API Key。人工重试是新的明确发送，已经产生的账号用量以服务商记录为准。

## 技术范围与数据流

后台连接管理器只允许固定 ChatGPT 原点，并在每次操作核对访问权限、顶层 `documentId` 及页面仍属于该原点。已有普通官网页面可承载请求，当前草稿和页面路由不因发送而被填写、点击或导航。没有合适页面时，创建 `active: false`、`pinned: true` 的代理标签。

网页 `MAIN` 环境注入本项目打包的客户端桥接器。桥接器仅识别当前官网页面加载的固定客户端模块形态，调用其正常请求和发送前检查流程，再向 `/backend-api/f/conversation` 发起一次对话请求。没有本地助手进程、自建云端服务器、校验算法复刻或失败后的自动重试。

官网会话和请求校验值留在页面客户端与请求闭包中。扩展后台只接收白名单状态、脱敏正文和会话关联标识；账号登录凭据不写入扩展存储、界面、诊断或日志。用户填写的 API Key 继续只在扩展可信上下文中管理，不送给 ChatGPT 页面。两种连接不会自动互相替代。

SSE 解析器只保留可见的最终文本回答及完成所需关联信息，支持完整快照和 delta v1。隐藏设置上下文、工具消息、推理通道及可执行界面数据不作为回答展示；Markdown 使用现有安全渲染器。复杂卡片、工具运行界面、图片与公式没有完整还原承诺。

这套通路使用官网内部接口和压缩客户端模块，**没有稳定的公开 SDK 兼容性保证**。官网更新、模型权限、账号额度、页面人工验证和网络策略均可能导致连接失败。实现会停止并给出固定分类；单纯 HTTP 403 不直接判定为验证码或账号额度问题。

## 独立验收

在自己的 Chrome 更新扩展，检查账号并保存模型后，完成以下操作：

1. 侧栏发送简短问题，收到完整回答；状态只有在完整结束后显示最近一次对话成功。
2. 追问上文，确认使用同一远端会话且回答能理解上下文。
3. 官网已有草稿时，在侧栏提问，草稿和官网会话页面保持原样。
4. 停止一轮较长回答，侧栏保留片段并明确标为停止，不自动补发。
5. 开启新对话，旧的 OpenAI 历史保留，新问题在新的远端会话中生成。
6. 触发或遇到连接失败时，复制的诊断能说明阶段与固定分类，且不暴露问题、账号或凭据。

首问、追问及停止均会向所选账号发起明确模型请求。当前测试结果应按模拟、真实请求状态和用户侧栏验收分别记录，不能互相替代。
