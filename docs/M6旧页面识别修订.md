# 0.9.1：已打开官网页的客户端识别

用户在 0.9.0 点击检查账号时，遇到“网页客户端暂不兼容”。真实官网页已经正常显示内容，旧的不可配置 v2 桥接器也已安装；页面的初始脚本和预加载标签均已移除，资源计时中也没有最初的运行时记录。0.9.0 只查找这些 DOM 标签，因而在读取模型之前报 `client/pageUnsupported`。此前使用新打开页面的测试遗漏了这个场景。

0.9.1 按顺序查找 DOM 资源、官网公开 `__reactRouterManifest.entry.imports` 和资源计时。只接受固定 ChatGPT 原点下、无查询参数或片段的已知运行时文件路径；各来源都有扫描上限。仅读取公开程序依赖列表，不读取路由数据、聊天内容或账号状态来发现资源。

新桥使用独立的 v3 属性，可与不可配置的旧 v2 共存。升级检查和对话只调用 v3，保留官网草稿和路由，无需为了替换旧桥刷新官网或新建标签。会话校验、模型发现和消息发送通路保持原有范围。

## 使用

在 Chrome 扩展管理重新加载阅窗，关闭再打开侧栏，点击“设置 → ChatGPT 账号 → 检查账号 / 刷新模型”，选择模型并保存。现有官网标签可以保持打开，无需手动刷新。

## 验证

生产网页适配器已在同一个未刷新的真实官网页执行账号检查，返回 `ready` 和 16 个可用模型；该页面保留旧 v2，并且初始 DOM 标签与资源计时均不可用。此项只检查账号，没有发送新问题。证据：[脱敏现场记录](验收证据/0.9.1/live-native-client-2026-10-29.json)。

新增回归覆盖 DOM 和资源计时均已清理、公开清单仍保留依赖的页面，以及来源优先级、URL 拒绝与扫描上限。生产扩展模拟覆盖已存在不可配置 v2 的同页升级，检查账号与两轮聊天成功，旧桥 start/poll/cancel 调用均为 0，页面文档、草稿和路由不变，没有重载或额外标签。

全量单测 **322/322**，Webapp 模拟 **14/14**。原有侧栏、划词、收藏和研究回归与发布包一致性以 [发布记录](验收证据/0.9.1/build-sha256.json) 为准。用户已安装扩展的原生侧栏仍需更新后体验验收。本轮真实检查不替代 0.9.0 的真实发送证据，也不声明已重新验证 0.9.1 的真实多轮生成。
