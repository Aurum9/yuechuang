# 侧栏连接恢复修订

日期：2026-10-30。版本：0.10.3。状态：已构建打包并通过发布核验；自动化与隔离浏览器验证通过，用户 Chrome 中的实际恢复效果待复测。

## 用户问题与定位边界

用户反馈：每次刷新助手状态后，侧栏会显示连接断开，随后无法继续聊天。

代码核查确认了两个独立连接：本地助手操作使用 Native Messaging Port，对话侧栏使用名为 `chat` 的 runtime.Port。助手状态检查结束时关闭其自己的 native Port；没有找到该操作主动关闭对话 Port 的代码路径。因此，目前不能仅凭操作顺序认定助手状态刷新直接关闭了聊天连接。

可以确认的恢复缺口是：旧侧栏只在初始化时连接一次。后台 worker 休眠、停止或重启导致对话 Port 断开后，当前侧栏文档不会重新建立连接，界面持续处于不可用状态。此次修订覆盖这条恢复路径；用户现场断开的直接诱因仍需结合实际复测判断。

0.10.2 用户已确认侧栏能收到真实回答，见[当时实机反馈](验收证据/0.10.2/用户实机复测.md)。该结论不能代替本轮后台断开与恢复场景的验收。

## 本轮改动

- 对话 Port 断开后使用有限退避，连续连接失败最多重试 3 次。新连接只发送 `chat:status` 读取当前状态；问题、停止和清空等命令仍由原操作触发。
- 重连保留当前侧栏文档与输入框草稿，从会话状态恢复已完成的历史。生成中的回答保留已收到的片段并标注中断；不自动续写、重发或切换连接。较短的旧检查点不覆盖已经显示的片段；额外保留的文字仅作为同一请求的本地显示，不进入后续请求上下文，也不用于其他请求或与原文分叉的回答。
- 每个 Port 使用独立版本标记，忽略被替换旧 Port 的迟到状态与断开事件。关闭文档时清理计时器和 Port，避免离开后继续重连。
- 连续恢复失败时给出明确提示；点击「对话」、返回侧栏或恢复窗口可见状态时允许重新尝试，保留草稿。
- 助手状态变化通知嵌入设置页；设置页初始化读取一次当前 SIWC 状态，使侧栏与设置显示同步。
- 后台被动就绪检查复用正在进行的助手检查。正在登录时只读取当前状态，不另发刷新来替换或取消登录。

本轮不修改助手 EXE，不要求因这次修订重装助手或重复授权。仍应以界面显示的实际授权状态决定是否需要重新登录。

### 旧版基线与本轮恢复证据

0.10.2 的[基线报告](../test-results/sidebar-reconnect/0.10.2-baseline.json)有 3 项检查通过，其中一项以复现连接断开后不可用为预期。测试经 CDP 确认目标 worker 的 `runningStatus` 变为 `stopped`，并观察 Chrome 触发实际 Port 断开；等待 4.5 秒后，原侧栏输入框仍禁用，状态仍为“连接已断开，请重新打开侧栏”。该结果复现了旧版缺少恢复路径的问题。

0.10.3 的[恢复报告](../test-results/sidebar-reconnect/0.10.3.json)有 5 项检查通过、0 失败。相同停止操作后，原侧栏文档恢复可用，未导航或重新加载；草稿、已完成历史保留，用户点击后仅发送一次。生成中的实际本机 SSE 请求会中断，已存检查点与下一条草稿可以恢复，测试统计自动重发 0 次。源 dist 和测试副本的生产字节保持一致。

16 项 UI 模拟另覆盖检查点比已显示内容更短的情形：保留已经看到的片段，后续刷新和新一轮开始也不把它回退为短文本；这份显示保护不会把中断文字写入后续模型上下文，跨请求及分叉文字也不复用。

实际 worker 测试只使用临时浏览器配置、本机模型夹具与虚构 Key。侧栏生产页面以扩展标签页打开，不验证用户 Chrome 原生停靠侧栏表面；不读取用户浏览器配置、助手或账号凭证，不发起真实模型请求。需要同时核对 `actualWorkerStopVerified`、`actualPortDisconnectVerified`、零自动重发、受测构建指纹及源 dist 未改变。

发布校验可选纳入 `test-results/sidebar-reconnect/0.10.3.json`。报告存在时必须通过上述核对并归档；缺失时明确记录未覆盖，不能把缺失当作测试通过。本轮最终报告已纳入，两个 ZIP 与最终受测构建一致，发布核验通过；报告归档在 `docs/验收证据/0.10.3`，见[试用核验记录](验收证据/0.10.3/siwc-trial-verification.json)。

## 用户复测步骤

1. 重新加载 0.10.3，重开侧栏；保留已安装助手和现有账号配置。
2. 在对话输入框写一段未发送文字，进入设置刷新助手状态，再返回「对话」，确认草稿仍在且可以发送。
3. 若短暂断开，确认界面显示恢复过程，恢复后由用户手动发送一次；检查没有额外自动发送。
4. 连续恢复失败时，按提示点击「对话」或返回侧栏再尝试，并记录实际状态。若需重复登录，应先确认界面是否确实报告授权失效。

目前不把代码修订或隔离浏览器结果写成用户现场问题已恢复。真实账号多轮、关闭全部官网标签页及助手操作结束后的退出情况继续按原试用范围验收。
